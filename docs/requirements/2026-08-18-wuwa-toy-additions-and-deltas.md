# 相对活动公告的新增与变更需求

基线公告：`鸣潮共鸣小剧场_活动公告.md` 与 `鸣潮拉海洛国风换装秀_活动公告.md`。未在本文件变更的赛道内容规范、原创规范、活动日程、奖项与公示规则保持有效。

| 编号 | 当前确认需求 | 实现结果 |
| --- | --- | --- |
| D1 | 两场活动合并为一个 Toy，公开端仅有两个赛道：共鸣小剧场、衣锦还裳。 | 首页直接在两个赛道间切换；投稿限额、初选和决赛票数均按赛道隔离。 |
| D2 | 投稿不再通过小站发帖，改为 Toy 内直接上传。 | 登录后上传图片或视频并提交资料。 |
| D3 | 排名不再以帖文纯点赞决定。 | 使用两阶段投票。 |
| D4 | 第一阶段每账号每赛道 3 次二选一，作品出现次数整体均衡。 | 服务端签发仅能使用一次、15 分钟过期的配对票据；数据库按实际有效对比记录曝光与胜场。 |
| D5 | 第一阶段每赛道由运营确定入围作品，再进入第二阶段。 | 白名单后台单独将作品设为「已入围」并控制是否公开展示。 |
| D6 | 第二阶段每账号每赛道每天 3 票，不能重复投同一作品。 | 服务器按中国标准时间记录每日票数与投票作品。 |
| D7 | 第二阶段展示票数、作者昵称和头像。 | 作品展廊显示这三项。 |
| D8 | 白名单运营方可查看投稿、作者、头像、阶段票数，并管理入围/展示。 | 独立受保护 `/ops`，公开导航与接口不暴露后台。 |
| D9 | 使用提供的雨景人物图；公开端顺序为标题/时间、规则、投稿、投票。 | 雨巷画卷视觉系统与窄屏优先布局。 |
| D10 | Toy 静态发布包最大 140MB、可反复更新、可自定义访问路径。 | `npm run check:bundle-size` 递归检查 `dist/`；Vite 读取 `VITE_TOY_BASE_PATH`；部署说明记录 Toy 更新和路径设置步骤。 |
| D11 | 设计过程不再通过本地协作页面展示。 | 仅通过本线程和仓库文档交付。 |
| D12 | 作品文件要在活动内直接上传，且运营可看到作者、头像、媒体和票数。 | 客户端从 Toy SDK 读取昵称/头像/开放标识；Worker 把媒体存入 R2、元数据和票数存入 D1，后台受白名单与服务端身份核验保护。 |
| D13 | 投稿必须符合两场原公告的媒体数量要求。 | 共鸣小剧场需至少 4 张图片；衣锦还裳需至少 3 张设计图或 1 个视频，前后端都会提示/校验。 |
| D14 | 删除公开首页中单独解释两阶段投票的两张描述卡；不要向普通用户暴露运营后台。 | 已移除该两卡说明；运营入口仍仅在受白名单保护的 `/ops`，公开导航不含后台。 |
| D15 | 投稿时必须由选手明确选择赛道，不能只依赖当前页面浏览的赛道。 | 投稿抽屉中展示两个直接可选赛道；所选赛道与当前浏览标签独立，并写入服务端投稿记录。 |
| D16 | 投稿时应明确作品类型（图片/视频）并进行检测。 | 抽屉按赛道显示可接受类型与大小，文件选择后显示识别出的图片/视频类型；Worker 同时校验 MIME、大小及二进制文件签名。 |
| D17 | 活动改为投稿、盲选、投票三个阶段，且三阶段均需设置时间。 | 运营后台可配置三阶段及起止时间；未设置时公开页显示“时间待运营发布”。 |
| D18 | 测试阶段可以全展示，正式活动时公开端只展示当前投票/投稿阶段。 | 运营后台增加测试预览开关；关闭时，前端与 Worker 写接口均只开放当前阶段。 |
| D19 | 右上角“活动规则”必须展示全量规则，包含免责声明、相关规定和反刷票/反攻击条款。 | 导航打开完整规则弹窗，覆盖资格、赛道、时间、投稿、投票、原创、公开展示、异常处理、免责声明与禁止刷票/攻击服务规定。 |
| D20 | 需要评估并增强对 SQL 注入、浏览器控制台篡改及大量请求/DoS 的防护。 | D1 全部使用参数化语句；Worker 不信任前端状态/控制台请求，使用服务端身份、阶段、原子投票与票据校验；增加请求大小限制和按账号/路由限流。生产仍要求 Cloudflare WAF、边缘限流与 DDoS 防护，详见部署文档。 |

## 已撤销的口头提议

“每账号每赛道最多提交五个作品”已被后续指令覆盖。当前有效规则为：**每账号每赛道限投 1 件**。

“公开端共四个赛道”和“第一阶段每赛道 5 次二选一”均已被后续指令覆盖。当前有效规则为：**两个赛道；第一阶段每账号每赛道 3 次二选一**。
