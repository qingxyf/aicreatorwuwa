# 鸣潮 AI 二创活动 Toy 实施记录

**目标：** 交付一个含两个赛道、直接投稿、两阶段投票和受白名单保护运营后台的 Bilibili Toy 活动站。

**架构：** `types -> config -> policy -> domain -> services -> adapters -> entrypoints -> app`。Toy SDK 仅在账户适配器中读取资料；D1/R2/HTTP/Workers 仅在适配器或入口层。公开端没有后台导航，`/ops` 由服务端白名单保护。

## 已执行内容

- [x] 配置两个赛道：共鸣小剧场、衣锦还裳；每账号每赛道只能提交一件作品。
- [x] 在前端读取 Toy 账户昵称、头像和开放标识，并将其映射为与厂商无关的 `Viewer`。
- [x] 以 R2 保存受类型与大小限制的图片/视频字节，以 D1 保存媒体所有者、投稿、票数、白名单与展示状态。
- [x] 服务端校验媒体所有权与赛道媒体规则：共鸣小剧场至少 4 张图片；衣锦还裳至少 3 张图片或 1 个视频。
- [x] 初选按实际曝光量选择低曝光作品；每次二选一由服务端签发一次性、15 分钟有效的票据，客户端不能伪造对比作品。
- [x] 决赛使用 D1 条件插入原子执行每日每赛道 3 票及「同一作品当日一次」限制；公开票数、初选曝光和胜场都由投票记录聚合得出，避免计数漂移。
- [x] `/ops` 显示作品、作者、头像、初选胜场/曝光、决赛票数，并独立管理入围与公开展示。
- [x] 使用用户提供的雨景背景图，配合 Ant Design 组件、微动效和响应式布局完成公开端；运营端不被公开端引用或展示。
- [x] 加入构建包 140MB 检查、架构检查和部署文档。

## 仍需由部署方提供的外部配置

- Bilibili 平台的可验证身份断言桥接服务地址和密钥；生产环境不会信任浏览器传来的用户 ID。
- Cloudflare D1/R2 资源 ID、Worker 域名，以及初始运营白名单的 Toy 开放标识。
- 在 Toy 控制台上传 `dist/`、设置访问路径并绑定生产 Worker URL。
