# 运营后台密码登录设计

## 目标

为 Bilibili Toy 活动的运营后台增加独立密码登录能力，解决当前 Toy `toyOpenId` 白名单无法直接维护的问题。公开活动页、投稿、盲选和投票逻辑保持不变；密码只用于 `/ops` 运营管理入口。

## 范围与不变项

- 仅保护运营接口：投稿列表、作品状态、展示状态和活动设置。
- 公开页面继续使用 Toy SDK 身份读取和现有投稿/投票接口。
- Toy 页面访问密码与运营后台密码是两套凭证。
- 不把 B 站 UID/MID 当作后台身份来源。
- 密码明文不进入仓库、Toy 静态包、日志或接口响应。

## 推荐方案

采用“服务端验证密码，返回短时签名会话令牌”的方案：

1. `POST /api/v1/ops/login` 接收密码，仅在服务端使用环境变量中的 scrypt 哈希校验。
2. 校验成功后返回短时、带过期时间的签名运营会话令牌；前端只在当前页面内存中保存令牌，刷新页面需要重新登录。
3. 运营请求通过 `Authorization: Bearer <ops-session>` 发送；服务端验证签名、用途和过期时间后才访问运营接口。
4. 登录失败按来源限流，避免密码猜测；错误统一返回 `operator_login_failed`，不泄露账号或校验细节。
5. 仍保留现有 `admins`/Toy 身份适配器作为后续可切换的身份方案，但密码模式下运营接口以有效会话令牌为准。

选择短时令牌而非跨域 Cookie，是因为 Toy 页面与 ECS API 属于不同站点，第三方 Cookie 可能被浏览器拦截；令牌只保存在页面内存中，不落盘。

## 配置

服务端新增以下环境变量：

- `OPS_ADMIN_PASSWORD_HASH`：使用 Node `scrypt` 生成的密码哈希（只部署在 ECS）。
- `OPS_SESSION_SECRET`：随机会话签名密钥（只部署在 ECS）。
- `OPS_SESSION_TTL_SECONDS`：可选，会话默认 30 分钟。

生成的 16 位初始密码只通过部署渠道交付，不写入 GitHub 或文档；部署后应立即保存到密码管理器。

## 前端交互

- `/ops.html` 初始显示“验证运营身份”卡片和密码输入框。
- 登录成功后加载现有作品表和活动设置。
- 登录失败显示稳定错误提示，不显示服务端堆栈。
- 页面刷新或会话过期后回到登录卡片；公开活动页不增加登录框或后台入口。

## API 与错误处理

- `POST /api/v1/ops/login`：密码正确返回令牌和过期时间，错误返回 401 `operator_login_failed`。
- 运营读写接口接受运营会话令牌；缺少或过期返回 401 `operator_session_required`。
- 现有 Toy 身份错误继续用于公开投稿/投票，不改变错误含义。
- 登录端点和运营写接口沿用请求大小、CORS、速率限制与结构化错误响应。

## 测试策略

- 单元测试：scrypt 哈希校验、错误密码拒绝、令牌签名/过期/用途校验。
- API 测试：登录成功后可读取运营列表；无令牌、错误令牌、过期令牌均不能访问运营接口。
- 回归测试：公开投稿和投票请求仍按 Toy 身份工作；普通页面不渲染运营密码表单。
- 构建检查：普通生产构建与 Toy 构建均通过，Toy 包自检确认相对资源和生产 API 配置。

## 风险与回滚

- 若 ECS 尚未配置新环境变量，运营登录明确返回配置错误，公开投稿/投票不受影响。
- 回滚时恢复旧版 Toy 包并重新启用 `admins` 白名单校验；不删除投稿或媒体数据。
